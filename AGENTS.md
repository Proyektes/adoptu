# Adopt-U - Agent Guidelines

## Project

Kotlin Multiplatform pet adoption platform. Helidon backend (JSON API only) + a static multi-page
site generated by the `frontend` module, deployed to CloudFront/S3 and decoupled from the backend
(see `frontend/src/jvmMain/kotlin/com/adoptu/site/SiteGenerator.kt`). This used to be server-side
rendered HTML via kotlinx.html directly from the backend (`UIRoutes.kt` + `com.adoptu.pages`) -
that coupling is why the backend used to also need Sass/CSS/static-asset serving; it doesn't
anymore.

## Conventions

- **MPA, not SPA - but static, not server-rendered**: Real multi-page navigation (no client-side
  router), but each page is a static `.html` file (see `frontend/src/jvmMain/kotlin/com/adoptu/
  site/pages/*.kt`, same kotlinx.html templates the backend used to render per-request) served
  directly from CloudFront/S3 - not an API response. Session/role state (nav visibility, admin-only
  page gating) is resolved client-side against `GET /api/auth/me` after load (`CommonModule.
  initAuthNav()` in `frontend/Common.kt`), not baked into the HTML at render time.
- **Kotlin-first**: Prefer Kotlin for everything — backend logic, frontend JS (via Kotlin/JS), and HTML generation (kotlinx.html). Avoid introducing Node.js, npm packages, or JS frameworks.
- **Clean Architecture**: Follow the ports/adapters pattern. Business logic lives in `services/`, interfaces in `ports/`, implementations in `adapters/`. Routes call services, services call ports.
- **Docs stay current**: When making important changes, update both `README.md` and `AGENTS.md` to reflect the new state.
- **Tests required**: New code must include tests. When removing code, review and remove its associated tests if no longer needed. Preferred ITs with business value. At least 90% coverage and 85 mutation test score. 

## Commands

```bash
./gradlew run              # Backend JSON API on :8080 (no pages - see :frontend:serveSite below)
./gradlew :backend:test    # Unit tests
./gradlew dockerUp         # Start Postgres + LocalStack + Mailpit for integration tests
./gradlew integrationTest  # Runs .*IT tests (requires dockerUp first)
./gradlew e2eTest          # Runs E2E tests with Playwright in Docker
./gradlew dockerDown       # Stop test containers
./gradlew shadowJar        # Build fat jar
./gradlew :frontend:compileSass  # Compile SCSS → CSS (needs the Dart Sass CLI, `sass`, on PATH)
./gradlew :frontend:generateSite # Render the static site to frontend/build/site/
./gradlew :frontend:serveSite    # generateSite + serve it locally (scripts/serve_site.py)
```

Run a single test: `./gradlew :backend:test --tests com.adoptu.SomeTest`

## Architecture

Multi-project build with `backend` (Helidon JSON API), `frontend` (Kotlin/JS client bundle + the
static site generator, see `SiteGenerator.kt`), and `common` (shared JVM/JS code, e.g. `Country`).

**Entry point**: `backend/src/main/kotlin/com/adoptu/Application.kt` → `ApplicationKt.module`
**Config**: `backend/src/main/resources/application.conf` (HOCON, env overrides via `ADOPTU_ENV`)

### Layer structure (`src/main/kotlin/com/adoptu/`)

| Directory | Purpose |
|---|---|
| `plugins/` | Ktor plugins (Routing, Sessions, Serialization, WebAuthn, Responses) |
| `routes/` | Route handlers grouped by domain |
| `services/` | Business logic, validation subpackage |
| `ports/` | Repository/storage/notification interfaces |
| `adapters/db/repositories/` | Exposed JDBC implementations of ports |
| `adapters/storage/` | S3 image storage adapter |
| `adapters/notification/` | SES email adapter |
| `pages/` | kotlinx.html page renderers |
| `di/` | Koin dependency injection (`AppModule.kt`) |
| `dto/input/` | Request DTOs |
| `dto/output/` | Response DTOs |

### Environment selection

`ADOPTU_ENV` defaults to `"prod"`. Config sections are keyed by `db.dev` / `db.prod`, `storage.dev` / `storage.prod`. The env value selects which section is used.

### Database

- Uses Exposed ORM with PostgreSQL
- `DatabaseFactory.init()` auto-creates tables and columns on startup
- Dev defaults: `jdbc:postgresql://localhost:5432/adoptu`, user `adoptu`, password `Ad0ptU`
- Creates a default admin user if none exists

### Integration tests

Require Docker. `docker-compose.test.yml` starts:
- PostgreSQL 15 on port **15432** (user: `testuser`, pass: `testpassword`, db: `testdb`)
- LocalStack on port **4567** (S3 only)
- Mailpit on port **1025** (SMTP) and **8025** (web UI at http://localhost:8025)

E2E tests use Playwright in Docker (`./gradlew e2eTest`). Tests run inside `mcr.microsoft.com/playwright/java` container with `--network host` so the embedded Ktor server is accessible. E2E tests are excluded from the regular `test` task.

### Browser E2E suite (npx Playwright) + seed data

`frontend/src/tests/e2e-verify.spec.ts` (run with `npx playwright test`; uses the system Chrome,
`npm install` first) drives a real browser against the locally running static site (not the
backend directly - pages only exist on the static site now). Prerequisites:

1. Backend up (`./gradlew run`, `ADOPTU_PORT` relocates it if :8080 is taken).
2. Static site up (`./gradlew :frontend:serveSite`, proxies `/api/*` to the backend - `ADOPTU_PORT`
   above must match what `serve_site.py`'s third arg / `:frontend:serveSite`'s default (`http://
   localhost:8080`) points at). The spec's `BASE` (default `http://localhost:4000`, override via
   `ADOPTU_BASE_URL`) points at this, not the backend - the backend must also be configured with
   the SAME `ADOPTU_BASE_URL` (its `baseUrl`, application.conf) or emailed verification/reset/
   magic-link URLs point at the wrong place.
3. Mailpit on :8025 (`docker compose up -d`).
4. Seed data: `bash scripts/load_test_data.sh`. All seeded users share password
   **SuperClave99!!** — it must satisfy AuthKit's `PasswordPolicy` (≥10 chars, ≥2 upper, ≥2 lower,
   ≥1 special, no fragment of the user's name/email — nothing containing "test", the seeded
   domain), and the hash in `scripts/test_data.sql` must be in AuthKit `PasswordHasher`'s exact
   format (argon2id m=16384,t=2,p=1, 16-byte salt, **32-byte digest** — its `verify()` compares a
   fixed 32-byte digest, so hashes with other digest lengths can never log in).

### Email (dev)

Dev mode uses SMTP via Mailpit. Run `./gradlew dockerUp` to start Mailpit, then view sent emails at http://localhost:8025. Default SMTP config: `localhost:1025` (no auth, no TLS). Override with `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_STARTTLS` env vars.

## Build quirks

- **Multi-project build**: `backend` (Ktor server) and `frontend` (Kotlin/JS) subprojects.
- **Custom `run` task**: `./gradlew run` is a custom `JavaExec` task (not from the `application` plugin, which conflicts with KMP).
- **SCSS → CSS flow**: source lives in `frontend/src/main/scss/*.scss` (real hand-authored, using `@use` partials -- see `_variables.scss`, `_base.scss`, `_layout.scss`, `_location-search-form.scss`, `_admin.scss`). `:frontend:compileSass` (an `Exec` task shelling out to the standalone Dart Sass CLI, `sass` on PATH -- no npm/Node) compiles it to `build/generated/scss/main/static/css/`, which `:frontend:generateSite` copies into the static site's `static/css/` alongside the compiled JS bundle. Moved here from `:backend` along with the page templates - the backend doesn't serve any static assets anymore.
- **Source dirs**: JVM sources are at `src/main/kotlin/` and `src/test/kotlin/` (non-standard for KMP, configured explicitly via `setSrcDirs`).
- `gradle.properties` has extensive `--add-opens` JVM args required for Kotlin 2.3+ and ByteBuddy
- Builder stage uses GraalVM native-image-community 25 (not Corretto). The Dockerfile only builds `:backend:jar`/`:backend:nativeCompile` (no Sass/Node dependency at all) - the static site (`:frontend:generateSite`) is a separate build/deploy pipeline (destined for S3 + CloudFront), not part of this image.
- `kotlin-js-store/` is auto-generated by Kotlin/JS (yarn.lock), safe to delete, recreated on build.
- AWS SDK `platform()` BOM is deprecated in Kotlin 2.3 — use explicit versioned dependencies instead.
- **E2E tests excluded from regular test run**: E2E tests in `com.adoptu.e2e.*` are excluded from `./gradlew :backend:test` and must be run via `./gradlew e2eTest` (requires Docker).
